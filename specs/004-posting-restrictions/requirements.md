# 004 投稿制限の解除導線 — requirements

略号: `GATE`

## 背景

Karotter は**メール認証と規約クイズの両方**が済むまで投稿を受け付けない。
karotator にはどちらの導線も無く、ユーザーは投稿しようとしてサーバーに弾かれるまで
理由を知る手段がない。

判定に使うフラグは既に `AuthUser` に載っている。

| フィールド | 意味 |
| --- | --- |
| `emailVerified` | 確認メールのリンクを踏んだか |
| `legalQuizPassed` | 規約クイズに 1 回でも合格したか |

**規約が更新されたことを知らせる帯（`LegalNoticeBanner`）とは別物。**
あちらは `legal/summary` の `version` と `legalNoticeSeenVersion` を比べるもので、
既に実装済み。004 では触らない。Karotter Web でも 2 本の帯が独立して並んでいる。

## 観測した仕様

出典は `https://karotter.com` のバンドル。`Layout`（帯）、`legal-quiz`（クイズ画面）、
`settings`（メール登録・再送）、`notificationTarget`（通知の遷移先）チャンク。
`dart run tool/grep_bundle.dart 'legal-quiz'` で再確認できる。

### 帯の出し分け

```js
!(user.emailVerified && user.legalQuizPassed) && !dismissed
```

右のボタンは 3 状態で変わる。**次にやることを 1 つだけ**出している。

| 状態 | ボタン | 行き先 |
| --- | --- | --- |
| メールアドレス未登録 | メールアドレスを登録 | 設定（アカウント） |
| 登録済み・未認証 | 再送 | `POST /auth/me/email/resend` |
| 認証済み・クイズ未合格 | クイズへ | 規約クイズ |

文言（クイズ未合格）:

> 規約クイズにまだ合格していないため投稿できません。右のボタンから受けてください（1回だけ）。

文言（メール未登録）:

> メールアドレスを登録し、規約クイズに1回合格すると投稿できるようになります。

閉じた記録はユーザーごとに持つ（`karotter_verify_banner_dismissed:{userId}`）。
**両方が真になった時点でその記録を消している。**

### 規約クイズ

`GET /auth/legal-quiz`

```jsonc
{
  "token": "...",
  "questions": [
    {
      "id": 1,
      "prompt":       {"ja": "...", "en": "..."},
      "document":     {"ja": "利用規約", "en": "Terms of Service"},
      "documentPath": "/terms",
      "options": [{"id": 1, "label": {"ja": "...", "en": "..."}}]
    }
  ]
}
```

既定は 5 問。各問は単一選択。全問埋まるまで採点できない。

`POST /auth/legal-quiz/grade`

```jsonc
// 送信
{"legalQuizToken": "<token>", "legalQuizAnswers": {"<questionId>": <optionId>}}

// 応答
{
  "passed": true,
  "legalQuizPassed": true,
  "questions": [{
    "id": 1,
    "options": [{"id": 1, "explanation": {"ja": "...", "en": "..."},
                 "isCorrect": true, "isSelected": true}]
  }]
}
```

採点後は**全ての選択肢に解説が出る**。正解・自分が選んだもの・それ以外で色を分けている。
「別の問題に挑戦」で引き直せる（回数制限は無い）。

合格時の文言は 3 分岐。

| 条件 | 文言 |
| --- | --- |
| `legalQuizPassed` かつ `emailVerified` | 合格です。投稿制限が解除されました。 |
| `legalQuizPassed` だが未認証 | 合格です。アカウントへの記録後、メール認証も完了すると投稿制限が解除されます。 |
| 未ログイン | 合格です。別の問題にも何回でも挑戦できます。 |

未成年向けの注意書きがあり、日本語のときだけひらがなを併記している。

> 18歳未満の方は、保護者・法定代理人と一緒にこのクイズに取り組めます。
> じゅうはっさいよりちいさいひとは おうちのひとや ほうていだいりにんと いっしょに といていいよ

### メール認証

| エンドポイント | 送信 | 応答 |
| --- | --- | --- |
| `POST /auth/me/email` | `{email}` | `{email, message}` |
| `POST /auth/me/email/resend` | なし | `{cooldownSeconds, message}` |
| `POST /auth/verify-email` | `{token}` | `{emailVerified, legalQuizPassed?, message}` |

再送は待ち時間を秒で返す。失敗時は 429 の retry から秒数を拾っている。
`token` は確認メールのリンク（Web の `/verify-email?token=...`）に入っている。

### 投稿はクライアントでは塞がれていない

Web に `canPost` に相当する分岐は無い。**作成ボタンも無効化していない。**
制限はサーバーだけが持ち、弾かれると SYSTEM 通知が届く。

```js
message.startsWith("規約クイズにまだ合格していないため投稿できません") → /legal-quiz
message.startsWith("まだメール認証が完了していないため投稿できません")  → /settings?tab=accounts
```

## 発見済みの不足

| # | 内容 | 影響 |
| --- | --- | --- |
| 1 | 投稿制限を知らせる導線が無い | 投稿しようとして弾かれるまで理由が分からない |
| 2 | 規約クイズを受けられない | **アプリだけでは投稿制限を解除できない** |
| 3 | メールアドレスの登録・再送ができない | 同上 |
| 4 | `emailVerified` / `legalQuizPassed` がどこからも読まれていない | フラグはあるのに使っていない |
| 5 | SYSTEM 通知の遷移先が一律 | 制限の通知を押しても何も起きない |

## 要件

### 知らせる

- **REQ-GATE-001** メール認証と規約クイズのどちらかが済んでいない間、システムは投稿できないことを知らせ続けること。
- **REQ-GATE-002** 知らせるとき、システムは次にすべきことを 1 つだけ示すこと。
- **REQ-GATE-003** 閲覧者が知らせを閉じたとき、システムはそれを記憶し、以後出さないこと。
- **REQ-GATE-004** 両方が済んだとき、システムは閉じた記憶を破棄すること。
- **REQ-GATE-005** もし未ログインならば、システムは知らせを出さないこと。
- **REQ-GATE-006** 投稿制限を伝える通知を選んだとき、システムは対応する画面へ移動すること。

### 規約クイズ

- **REQ-GATE-007** システムは規約クイズを取得し、設問と選択肢を提示すること。
- **REQ-GATE-008** 全ての設問に答えるまで、システムは採点を行わせないこと。
- **REQ-GATE-009** 採点したとき、システムは全ての選択肢について、正解か・自分が選んだか・解説を示すこと。
- **REQ-GATE-010** 採点したとき、システムは合否を示すこと。
- **REQ-GATE-011** 合格したとき、システムは投稿制限が解除されたかどうかを区別して伝えること。
- **REQ-GATE-012** 閲覧者が求めたとき、システムは別の問題を取り直せること。
- **REQ-GATE-013** システムは各設問について、根拠となる規約文書へ移動する手段を示すこと。
- **REQ-GATE-014** システムは未成年向けの注意書きを、ひらがなの併記とともに示すこと。

### メール認証

- **REQ-GATE-015** システムはメールアドレスを登録・変更できること。
- **REQ-GATE-016** システムは確認メールを再送できること。
- **REQ-GATE-017** 再送に待ち時間があるとき、システムは残り時間を示し、その間は再送させないこと。
- **REQ-GATE-018** システムは確認リンクを端末の既定ブラウザで開かせること。認証トークンをアプリで扱わないこと。
- **REQ-GATE-019** 閲覧者がブラウザから戻ったとき、システムは認証状態を取り直せること。

### 状態の保持

- **REQ-GATE-020** 合格や認証で状態が変わったとき、システムは手元の控えも更新すること。
- **REQ-GATE-021** システムは投稿の操作を塞がないこと。可否の判断はサーバーに委ねること。

### 堅さ

- **REQ-GATE-022** クイズの取得や採点に失敗したとき、システムは理由を示し、他の画面を止めないこと。
- **REQ-GATE-023** 設問数や選択肢数が変わっても、システムは同じように扱えること。

## 未解決

| 項目 | 内容 |
| --- | --- |
| 合格の記録条件 | `passed` が真でも `legalQuizPassed` が偽になる場合がある（Web が両者を分けている）。どんなときかは未確認 |
| 再送の待ち時間 | `cooldownSeconds` の既定値と上限が未確認 |
| メール変更時の扱い | 変更すると `emailVerified` が偽に戻るのか未確認 |
| 設問の言語 | `prompt` / `label` / `explanation` は `{ja, en}`。karotator は日本語のみ出す |
| 通知の判定 | 本文の前方一致で見分けている。サーバーが文言を変えると壊れる |

## 非目標

- 新規登録。`POST /auth/register` は Turnstile を要求するため別件（[todo.md](../../todo.md)）。
- 英語表示。`{ja, en}` の en 側は取れるが、アプリ全体の英語化と一緒に扱う。
- ディープリンク / App Links による認証トークンの受け取り。
  ドメイン側に `assetlinks.json` が要り、非公式クライアントでは確実に効かせられない。
- 規約更新の帯（`LegalNoticeBanner`）。既に実装済みで、これとは独立している。
- 投稿画面での事前ブロック。REQ-GATE-021 の通り行わない。
