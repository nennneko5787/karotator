# 005 本文とリアクションの装飾 — requirements

略号: `RICH`

## 背景

Karotter の本文とリアクションには、karotator が扱えていない記法が 3 つある。
どれも「読めない」ではなく「**生の記号や識別子がそのまま出る**」という壊れ方をする。

| # | 何が出るべきか | 今 karotator に出るもの |
| --- | --- | --- |
| 1 | pro リアクションの画像 | `pro:otsukaresama` という文字列 |
| 2 | ルビ付きの文字 | `漢字《かんじ》` |
| 3 | 伏せられた文字 | `\|\|ネタバレ\|\|` |

1 は実際にタイムラインで確認済み。2・3 は記法がバンドルにあるので、
使われれば同じことが起きる。

## 観測した仕様

出典は `https://karotter.com` のバンドル。`proReactions` / `PostRichText` /
`subscription` チャンク。`dart run tool/grep_bundle.dart 'proReactions'` で再確認できる。

### pro リアクション（カスタム絵文字）

`proReactions` チャンクに **89 件のテーブルが丸ごと埋まっている**。
一覧を返す API は無い。`legalDocuments` と同じ状況。

```jsonc
{"code": "pro:otsukaresama", "slug": "otsukaresama",
 "label": "おつかれ様", "labelEn": "Nice work",
 "assetUrl": "/reactions/pro/otsukaresama.png"}
```

- `ReactionSummary.emoji` にこの `code` がそのまま入る
- 画像は Karotter Web のホスト基準の相対パス
- `label` はツールチップと読み上げに使う

**付けられるのは PRO プランだけ。** Web の判定はこう。

```js
if (isProReaction(code) && !isPro && !alreadyReacted) → 弾く
```

既に付いているものは誰でも見えるし、自分が付けたものは PRO を切らしても外せる。

プランの判定は素の `subscriptionPlan` ではない。

```js
effectivePlan(user) =
  plan !== "FREE" && (status === "ACTIVE" || status === "TRIALING")
    && (!activeUntil || activeUntil > now)
      ? plan : "FREE"
```

### ルビ

pixiv や小説投稿サイトと同じ記法。

```
｜漢字《かんじ》     ← ｜ または | で base を明示
漢字《かんじ》       ← 空白を含まない直前の塊が base
```

```js
/^(?:[|｜]([^《》\n]+)|([^\s《》｜|]+))《([^《》\n]+)》$/u
```

### 伏せ字

```
||ネタバレ||
```

```js
/(\|\|[\s\S]+?\|\|)/g
```

本文はまず伏せ字で分割し、その中身をさらにトークン化している。
つまり**伏せ字の中にも URL やルビが入りうる**。

### 本文のトークン化

```js
/(\s+
 |(?:https?:\/\/|www\.)[^\s<>()]+[^\s.,!?<>()]
 |#[\p{L}\p{N}_]{1,50}
 |@[A-Za-z0-9_]{1,30}
 |(?:[|｜][^《》\n]+|[^\s《》｜|]+)《[^《》\n]+》)/gu
```

karotator の `TextAgent` は URL とメンションだけを見ている。
`www.` 始まりの URL とハッシュタグも取りこぼしている。

## 発見済みの不足

| # | 内容 | 影響 |
| --- | --- | --- |
| 1 | pro リアクションを画像にできない | **リアクション欄に `pro:xxx` が生で出る**（確認済み） |
| 2 | pro リアクションの一覧を持たない | ピッカーから付けられない |
| 3 | プランの実効判定が無い | PRO 限定かどうかを判断できない |
| 4 | ルビを解釈しない | `漢字《かんじ》` が生で出る |
| 5 | 伏せ字を解釈しない | `\|\|ネタバレ\|\|` が生で出て、しかも**中身が丸見え** |
| 6 | `www.` 始まりの URL を拾わない | リンクにならない |

5 は見た目の問題では済まない。伏せる意図で書かれたものが伏せられない。

## 要件

### pro リアクション

- **REQ-RICH-001** リアクションが pro リアクションのとき、システムは対応する画像を示すこと。
- **REQ-RICH-002** 画像を出せないとき、システムは日本語の名前を代わりに示すこと。
- **REQ-RICH-003** システムは pro リアクションの名前を、押せる範囲の説明として示すこと。
- **REQ-RICH-004** システムは pro リアクションを一覧から選べるようにすること。
- **REQ-RICH-005** 閲覧者が PRO でない間、システムは pro リアクションを新たに付けさせないこと。
- **REQ-RICH-006** 既に付いている pro リアクションは、閲覧者が PRO でなくても表示すること。
- **REQ-RICH-007** 閲覧者が自分で付けた pro リアクションは、PRO でなくなっても外せること。
- **REQ-RICH-008** システムは契約の状態と期限を加味して、実効的なプランを判定すること。

### 本文

- **REQ-RICH-009** 本文にルビ記法があるとき、システムは読みを添えて示すこと。
- **REQ-RICH-010** 本文に伏せ字記法があるとき、システムは中身を隠して示すこと。
- **REQ-RICH-011** 閲覧者が伏せ字に触れたとき、システムは中身を示すこと。
- **REQ-RICH-012** 伏せ字の中にある URL・メンション・ルビも、システムは同じように扱うこと。
- **REQ-RICH-013** システムは `www.` で始まる URL もリンクとして扱うこと。

### 一覧の維持

- **REQ-RICH-014** システムは pro リアクションの一覧をバンドルから機械的に取り出す手段を提供すること。
- **REQ-RICH-015** 生成した一覧は手で編集しないこと。

### 堅さ

- **REQ-RICH-016** 知らない `pro:` 識別子を受け取ったとき、システムは落ちずにその文字列を示すこと。
- **REQ-RICH-017** 記法が入れ子や不完全であっても、システムは本文を表示し続けること。

## 未解決

| 項目 | 内容 |
| --- | --- |
| ハッシュタグ | Web はリンクにして検索へ飛ばす。karotator は検索が未実装なので 005 では扱わない |
| 画像の取得元 | `assetUrl` は Web ホスト基準。CDN が別にあるかは未確認 |
| pro リアクションの増減 | テーブルはバンドル埋め込みなので、増えたら再生成が要る |
| 伏せ字の既定 | Web が一度開いた伏せ字を覚えるかは未確認 |

## 非目標

- ハッシュタグのリンク化（検索画面が無い）。
- 英語表示。`labelEn` は生成物に含めるが、出すのは日本語のみ。
- PRO プランの購入導線。
- 文字数上限（`PRO:7000 / PLUS:1000 / FREE:200`）や添付容量の反映。投稿画面の別件。
