# 006 本文の Markdown — requirements

略号: `MD`

## 背景

カロートの本文は**プレーンテキストではない。Markdown として描かれている。**

karotator は本文を素の文字として出し、URL・メンション・ハッシュタグ・ルビ・
伏せ字だけを解釈している（005）。そのため `# 見出し` や `**太字**` が
記号のまま画面に出る。

Karotter Web は `react-markdown` に `remark-gfm` と独自プラグインを載せ、
コードブロックは highlight.js で色分けしている。005 で実装したルビや伏せ字は
**その上に乗っている追加記法**で、Markdown を解いた後の文字に掛かる。

## 観測した仕様

出典は `PostRichText` チャンク。`dart run tool/grep_bundle.dart 'karotter-markdown'`
で再確認できる。

### 使える記法

コンポーネント対応表に出ている要素から分かるもの。

| 記法 | 出るもの |
| --- | --- |
| `# 見出し` 〜 `###### ` | `h1` 〜 `h6` |
| `**太字**` | `strong` |
| `~~打ち消し~~` | `del` |
| `> 引用` | `blockquote` |
| `- 箇条書き` / `1. ` | `li` |
| `[文字](URL)` | `a` |
| 表 | `table` / `th` |
| `` `コード` `` / ` ```lang ` | `code` / `pre`（言語別の色分け付き） |
| 下線 | `u` |

`remark-gfm` が入っているので、表・打ち消し・自動リンク・脚注が有効。

### 独自記法 `-# `

行頭の `-# ` を剥がし、小さい段落として描く（`karotter-markdown-subtext`）。
remark の標準ではなく Karotter の独自プラグイン。Discord と同じ記法。

```js
if (!node.value.startsWith("-# ")) return;
node.value = node.value.slice(3);
// className に "karotter-markdown-subtext" を足して <p> にする
```

### 引用元やプレビューでは解釈しない

`lightweight` を立てると、Markdown を通さず**素の段落 1 つ**として描く。
引用カードや折り畳み表示がこれ。

```js
lightweight
  ? <div class="karotter-rich-text"><p class="karotter-markdown-paragraph">…</p></div>
  : <ReactMarkdown remarkPlugins={[gfm, …]} rehypePlugins={[…]}>
```

### 見出しとハッシュタグは別物

Markdown の見出しは `#` の**後ろに空白**が要る。`#にんじん` は見出しにならず
ハッシュタグのまま。karotator のトークナイザは `#[\p{L}\p{N}_]{1,50}` を
ハッシュタグとして拾うので、`# 見出し` と衝突しない。

## 発見済みの不足

| # | 内容 | 影響 |
| --- | --- | --- |
| 1 | Markdown を解釈しない | `# ` `**` `>` `-` などが記号のまま出る |
| 2 | `-# ` を解釈しない | `-# ` が本文に残る |
| 3 | 引用元でも本文と同じ扱いをしている | Web は引用元で Markdown を解かない |

## 要件

### 本文

- **REQ-MD-001** システムは本文を Markdown として解釈すること。
- **REQ-MD-002** システムは見出しを、水準に応じた大きさで示すこと。
- **REQ-MD-003** システムは強調・打ち消し・下線を示すこと。
- **REQ-MD-004** システムは引用を、本文と区別できる形で示すこと。
- **REQ-MD-005** システムは箇条書きと番号付きの並びを示すこと。
- **REQ-MD-006** システムは Markdown のリンクを、押せる形で示すこと。
- **REQ-MD-007** 行頭に `-# ` があるとき、システムはその行を小さく示すこと。
- **REQ-MD-008** システムはコードを等幅で、本文と区別できる形で示すこと。
- **REQ-MD-015** コードブロックに言語が指定されているとき、システムは言語に応じて色分けすること。
- **REQ-MD-016** 知らない言語や言語の指定が無いときも、システムはコードを崩さずに示すこと。
- **REQ-MD-017** 表が画面に収まらないとき、システムは表だけを横に送れるようにすること。本文は横に送らせないこと。

### 既存の記法との共存

- **REQ-MD-009** Markdown を解いた後の文字に対して、システムは URL・メンション・ハッシュタグ・ルビ・伏せ字を今までどおり解釈すること。
- **REQ-MD-010** ハッシュタグは見出しとして解釈しないこと。

### 出し分け

- **REQ-MD-011** 引用元やプレビューでは、システムは Markdown を解釈せず素の文字として示すこと。

### 堅さ

- **REQ-MD-012** 記法が壊れていても、システムは本文を表示し続けること。
- **REQ-MD-013** 知らない要素を受け取ったとき、システムは中身の文字を落とさずに示すこと。
- **REQ-MD-014** システムは本文の描画で外部へ通信しないこと。

- 英語表示。
